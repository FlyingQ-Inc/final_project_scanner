# Network Vulnerability Scanner and Report Generator

## Overview

This project is a Bash-based network security scanner developed for NTS370. The scanner identifies open ports, detects running services, checks for potential vulnerabilities, and generates a structured security report with remediation recommendations.

The program combines Nmap scanning, service version analysis, vulnerability scripts, and information from the National Vulnerability Database to provide a more complete assessment of an authorized target.

## Purpose

The purpose of this project is to demonstrate practical skills in:

- Linux command-line operations
- Bash scripting and automation
- Network scanning and service identification
- Vulnerability identification and analysis
- API integration and JSON processing
- Input validation and error handling
- Security reporting and documentation
- Ethical network security practices

## Required Tools

The scanner depends on the following tools:

- Bash
- Nmap
- curl
- jq

Bash runs the script, Nmap performs the network scan, curl communicates with the National Vulnerability Database, and jq processes the returned JSON data.

The scanner can also operate without NVD lookups when offline mode is selected.

## Project Files

- `netscan.sh`: The primary network vulnerability scanner.
- `README.md`: Project documentation and usage instructions.
- `report.txt`: An example security report generated by the scanner.
- Optional HTML reports can also be generated when the appropriate option is selected.

## How to Use the Scanner

1. Confirm that the required tools are available in your environment.
2. Ensure the scanner script has permission to execute.
3. Select a target IP address or hostname that you own or have explicit permission to scan.
4. Run the scanner with exactly one target.
5. Include optional features as needed, such as HTML reporting, operating system detection, or custom port selection.
6. Allow the scan and vulnerability analysis to complete.
7. Review the generated report for open ports, potential vulnerabilities, and recommended remediation actions.
8. Save the completed script and report for submission or future reference.

## Available Options

| Option | Purpose |
| --- | --- |
| `-h` | Displays information about the available scanner options. |
| `-H` | Generates an additional HTML version of the report. |
| `-n` | Disables National Vulnerability Database lookups for offline scanning. |
| `-O` | Enables operating system detection when sufficient privileges are available. |
| `-P` | Skips host discovery when an authorized target does not respond to discovery probes. |
| `-o` | Specifies a custom filename for the generated text report. |
| `-p` | Limits the scan to selected ports or port ranges. |

The scanner accepts exactly one target IP address or hostname. If no target or multiple targets are supplied, it displays an error and stops.

## Scanning Methodology

The scanner performs a single Nmap scan and reuses the collected results throughout the analysis process. This avoids duplicate scans and ensures that the report sections are based on the same findings.

The scan uses several Nmap features:

- Service version detection identifies software products and version information.
- Vulnerability scripts check detected services for known security weaknesses.
- Script timeouts prevent individual vulnerability checks from running indefinitely.
- Host timeouts limit how long the scanner spends on an individual system.
- Port-state explanations provide additional information about why ports were identified as open.
- Optional operating system detection attempts to identify the target operating system.
- Optional port selection limits the scan to specific ports or ranges.
- Optional host discovery bypass can be used when an authorized target blocks discovery requests.

The scanner filters Nmap output using an anchored expression so that only valid open-port entries are included in the report.

## Vulnerability Identification

The scanner identifies potential security issues using four different methods.

### 1. Service Exposure Analysis

The scanner checks for services that may introduce unnecessary risk when exposed to a network.

Examples include:

- FTP
- SSH
- Telnet
- HTTP
- SMB
- Database services
- NFS
- Docker management interfaces
- Remote Desktop Protocol
- VNC
- Redis
- Elasticsearch
- MongoDB

Exposed services are reported as potential security risks. An open port is not automatically treated as confirmation that a service is vulnerable.

### 2. Software Version Analysis

The scanner compares detected product versions against known vulnerable versions associated with documented CVEs.

| Software | Version or Condition | Associated Vulnerability |
| --- | --- | --- |
| vsftpd | Version 2.3.4 | CVE-2011-2523 |
| ProFTPD | Version 1.3.5 | CVE-2015-3306 |
| Apache HTTP Server | Version 2.4.48 or earlier | CVE-2021-40438 |
| Apache HTTP Server | Version 2.4.49 | CVE-2021-41773 |
| Apache HTTP Server | Versions 2.4.49 and 2.4.50 | CVE-2021-42013 |
| OpenSSH | Versions earlier than 7.3 | CVE-2016-6210 |
| OpenSSH | Versions through 7.7 | CVE-2018-15473 |
| MySQL | Version 5.5.23 | CVE-2012-2122 |
| nginx | Version 1.3.9 | CVE-2013-2028 |
| Samba | Version 3.0.20 | CVE-2007-2447 |
| UnrealIRCd | Version 3.2.8.1 | CVE-2010-2075 |
| Microsoft IIS | Version 6.0 | CVE-2017-7269 |
| Exim | Versions 4.87 through 4.91 | CVE-2019-10149 |
| Elasticsearch | Version 1.4.2 | CVE-2015-1427 |
| OpenSSL | Versions 1.0.1 through 1.0.1f | CVE-2014-0160 |

These findings identify potentially affected software versions. Additional verification may be necessary because some vendors apply security fixes without changing the displayed product version.

### 3. Nmap Scripting Engine Analysis

The scanner evaluates results from Nmap vulnerability scripts to identify additional potential weaknesses.

Positive findings and referenced CVE identifiers are included in the report. Results explicitly identified as not vulnerable are excluded to reduce false positives.

### 4. National Vulnerability Database Lookups

The scanner can query the National Vulnerability Database using detected product names and version numbers.

The API results are processed to identify:

- CVE identifiers
- Vulnerability descriptions
- Severity ratings
- Associated product information
- Reference links

The scanner limits the number of API requests to reduce unnecessary traffic and respect public rate limits.

If the NVD service cannot be reached, the scanner continues using locally identified findings and Nmap vulnerability results.

## Input Validation and Error Handling

The scanner includes safeguards designed to prevent incorrect operation.

These safeguards include:

- Requiring exactly one target IP address or hostname.
- Rejecting invalid or missing targets.
- Validating custom port numbers and ranges.
- Confirming that required dependencies are available.
- Verifying that operating system detection has sufficient privileges.
- Checking the exit status of the Nmap scan.
- Detecting unreachable or unresolved targets.
- Reporting NVD communication failures without discarding scan results.
- Detecting report generation errors.
- Preventing duplicate vulnerability entries.

## Report Contents

The generated security report includes:

1. Report title.
2. Target IP address or hostname.
3. Date and time of the scan.
4. Nmap scan configuration.
5. Executive summary.
6. Number of identified open ports.
7. Total vulnerability and exposure findings.
8. Finding totals organized by severity.
9. Operating system information when available.
10. Open ports and detected services.
11. Potential vulnerabilities and associated CVEs.
12. Vulnerability descriptions and reference information.
13. National Vulnerability Database lookup results.
14. Specific remediation recommendations.
15. Report completion notice.

Reports use timestamped filenames unless a custom report filename is selected.

An optional HTML report can also be generated for improved readability.

## Remediation Recommendations

The scanner provides recommendations based on the services and vulnerabilities it identifies.

Examples include:

- Replacing insecure Telnet access with encrypted remote administration.
- Restricting SSH access to approved systems and using stronger authentication.
- Removing outdated or backdoored software.
- Updating vulnerable Apache, OpenSSH, MySQL, and other services.
- Disabling unnecessary public access to databases.
- Restricting SMB, NFS, Redis, and MongoDB to trusted networks.
- Protecting Docker management interfaces.
- Enabling encryption for web applications and administrative services.
- Reviewing vendor security advisories for identified CVEs.
- Replacing potentially exposed certificates and private keys when appropriate.

## Ethical Considerations

Network scanning should only be performed against systems that you own or have explicit permission to assess.

Before running a scan:

1. Confirm that the target is authorized.
2. Identify any applicable organizational policies.
3. Understand the potential impact of vulnerability scanning.
4. Avoid scanning systems outside the approved scope.
5. Protect generated reports because they may contain sensitive information.
6. Report discovered vulnerabilities responsibly.

Nmap vulnerability scripts can generate substantial network traffic and may affect unstable or sensitive systems. The user is responsible for ensuring that all scanning activities comply with applicable laws, policies, and authorization requirements.
